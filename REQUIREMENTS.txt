Build a complete, polished browser-based game-show app for my actual Family Feud-style trivia night. Implement and test the working app. Do not stop after creating a plan or mockup.

Goal

Create a reusable game-show application with three connected areas:

Audience Display: shown full-screen on a TV or projector.
Presenter View: private controls and answers visible only to the host.
Game Editor: create, paste, import, edit, reorder, and save games for future trivia nights.

The app must include the complete game data provided below and be easy to reuse with entirely different questions later.

Technical direction

Build a responsive client-side web app. Prefer React, TypeScript, and Vite unless the existing project clearly calls for another stack.

Requirements:

No database or paid service.
No OpenAI API or other API is required.
All core gameplay must work without an internet connection after installation.
Store game data and current progress locally.
Use a maintainable, component-based architecture.
Keep game content separate from interface code.
Include import and export using a clear, versioned JSON format.
If Sites is available, use it for previewing or publishing, while keeping the application capable of running locally.
Include simple Windows instructions and, if practical, a launcher that starts the app and opens it in the browser.

Appropriate transitions and game-show styling

Never show presenter instructions, unrevealed answers, editing controls, keyboard shortcuts, or host notes on the Audience Display.

Window synchronization

Use BroadcastChannel for real-time synchronization between the Presenter View and Audience Display, with a sensible fallback such as local-storage events.

The Audience Display must:

Receive the current state when it opens
Reconnect if refreshed
Stay synchronized with the presenter
Display the timer accurately using timestamps to avoid countdown drift

Provide separate routes or URLs such as:

/presenter
/display
/editor

An equivalent hash-based routing system is acceptable if it improves static hosting compatibility.

How dual-screen use should work

Include an in-app help panel with these instructions:

Connect the TV to the laptop.
In Windows display settings, choose “Extend these displays.”
Open the Presenter View on the laptop.
Click “Open Audience Display.”
Drag the new audience window onto the TV.
Put the audience window into fullscreen mode.
Keep the Presenter View on the laptop.

Also provide a single-screen fallback for mirrored displays:

The audience board fills the screen.
The host controls it with keyboard shortcuts.
Unrevealed answers and private controls remain hidden.
No host-facing instructions appear on the board.

The presenter should also be able to share only the Audience Display window in Zoom, Teams, or another screen-sharing service.

Gameplay controls

Answers must be revealable in any order. If a contestant gives answer number 5 first, the presenter can reveal number 5 immediately.

Provide both clickable controls and keyboard shortcuts:

Number keys 1 through 8: reveal the corresponding ranked answer
T: start or pause timer
R: reset timer
X: add a strike
Z: remove a strike
N or Right Arrow: next question
P or Left Arrow: previous question
F: fullscreen Audience Display
U: undo last presenter action
Escape: close overlays without changing the game

Keyboard shortcuts must be disabled while the user is typing in an editor field.

Include a visible shortcut reference in Presenter View only.

Option to restart the timer quickly for the next contestant
